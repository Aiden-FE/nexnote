## 背景

用户报告：编辑 MD 文件后（双栏模式），预览区顶部出现错误横幅：

> 预览更新失败（整页解析失败）：Invalid content for node type listItem · 下方内容已过期

此后预览不再更新；改回/清空源码也没有自动重新渲染，切换到其他模式再切回双栏模式也没用，没有一键重试或强制重渲的入口。

## 现状（triage 核实，含真实内核复现）

**错误来源**：`RangeError: Invalid content for node type listItem` 只会由 prosemirror-transform 的 `setNodeMarkup` 在 `validContent` 失败时抛出。setMarkdown 路径上唯一调用方是内核的 UniqueID（块 ID）扩展的 `appendTransaction`：它对缺 `blockId` 的块调 `setNodeMarkup`，此时校验节点内容。

**非法 JSON 的产生点**：parseMarkdown 产 TipTap JSON 时不经 schema 校验（`enableContentCheck` 关闭，非法结构照常入库），`setContent` 后由 UniqueID 补 ID 时才炸。内核的自定义有序列表分词器在**有序列表项正文为空且后面跟缩进块**时，把全部内容划入 blockLines，产出的 list_item token 内容以 block token 开头、没有前置 paragraph——而 schema 要求 listItem 首子块是 paragraph。于是产出 `listItem<[bulletList]>` 或 `listItem<[table]>` 的非法 JSON。

**已用真实内核代码复现的触发输入**（该 listItem 无 `^blockId` 锚点是必要条件）：

```markdown
1. 
   - a
```

```markdown
1. 
   | t |
   | - |
```

即：`N. `（编号后无正文，须带尾随空格）下一行跟**缩进的列表或表格**。缩进的标题/引用/代码块因被归入 paragraph 段而幸免；无序列表走 marked 内建分词器，未观察到触发形态。**触发面集中在有序列表自定义分词器。**

**恢复路径核实（解释用户的全部观察）**：

- 双栏 ↔ 预览切换：LivePreview 不卸载，错误 state 原样残留——用户看到"切模式没用"。
- 双栏 → 源码 → 双栏：LivePreview 卸载重建、重新初始化渲染。**若横幅仍出现，说明当前文档文本确定性不可解析**——只要 `N. ` 空正文 + 缩进块的结构还在，任何模式、任何重开都必现。用户"清空改回合法内容仍不行"很可能是没有定位到真正的触发行（或编辑后自动保存未落盘、重开读到的是坏内容）。
- markdown 文档的视图切换守卫不生效：视图切换请求对 markdown 文档直接放行，不经过整页解析守卫（该守卫只对 legacy tab 生效）——能触发解析失败的文档可以自由进出所有视图，横幅是唯一暴露面。

**"无手段恢复"核实**：错误横幅是纯文本提示，无按钮、无快捷键、无命令面板入口。唯一的恢复途径是用户自己找到并改掉源码里的触发结构（横幅完全不给出行号/线索）。**恢复手段缺失属实。**

**测试空白**：live-preview 相关测试只覆盖首帧/防抖/目录/高亮，未覆盖 setMarkdown 抛错与横幅路径；kernel 侧 round-trip 矩阵无"空正文有序项 + 缩进块"用例；`Invalid content` 全仓测试零命中。

## 期望行为

1. **解析层（根因）**：`1. `（空正文有序项）后跟缩进列表/表格时，parseMarkdown 产出的 listItem JSON 必须满足 schema（首子块为 paragraph，如先产一个空 paragraph 再接 block），`setMarkdown` 不再抛 `Invalid content for node type listItem`。对常见非空正文有序项行为不回归。
2. **降级防线**：setMarkdown 失败时，预览保留上一次内容并给出横幅的既有语义保留；但错误信息应包含可定位线索（如失败的行号或触发片段摘要）。
3. **恢复手段**：横幅提供显式重试入口（按钮即可）：点击后用当前 markdown 重新走一次渲染，成功则清横幅、失败则刷新错误信息。同时，自动恢复路径保持：后续源码变为可解析时，下一次防抖渲染成功即自动清横幅。
4. 视图切换语义不变（本票不要求把解析守卫接入 markdown 文档的视图切换）。

## 关键接口

- 内核有序列表自定义分词器中"空正文项 + blockLines"的内容划分逻辑：需保证产出的每个 list_item token 的内容以 paragraph 开头（空正文时插入空 paragraph），或等价方案使 JSON 满足 `listItem: content: "paragraph block*"` 约束。
- LivePreview 的渲染失败横幅：新增重试动作（复用既有渲染回调即可，无需新管线）；错误文案词条（zh/en 双语目录）需支持携带定位线索，注意遵循 ADR-0023 的 message catalog 约定。
- `parseMarkdown` → `setContent` 的 JSON 组装路径不新增 schema 校验全量扫描（性能敏感，保持 `enableContentCheck` 现状；修分词器产出即可）。

## 验收标准

- [x] kernel 单测：`1. \n   - a\n` 与 `1. \n   | t |\n   | - |\n` 两个输入经 parseMarkdown 产出 schema 合法 JSON（用真实 schema 逐节点 `validContent` 断言），setMarkdown 全流程不抛错。
- [x] round-trip：上述输入 parse → serialize 后列表/表格结构保留、不产生可见垃圾字符；非空正文有序项（含嵌套）既有用例零回归。

## 修复与验收证据（2026-10-11）

- 根因修复：`parseMarkdown` 管线新增 `normalizeListItemContent`（packages/kernel/src/markdown/pipeline.ts）——首子块不是 paragraph 的 listItem/taskItem 补一个空 paragraph，JSON 对 schema 合法。预览/块编辑/replaceRangeWithMarkdown 等全部宿主共享该管线，一处修复全覆盖。
- 防线补强：LivePreview 错误横幅新增「重试」按钮（`data-testid="preview-retry"`），用最新文本立即重走渲染，成功清横幅、失败刷新错误；自动恢复路径（后续文本可解析时防抖渲染清横幅）保留。
- 验证：挂载即触发形态（initialMarkdown 为 `1. \n   - a\n`）成功解析；真实 schema `validContent` 全文档断言。
