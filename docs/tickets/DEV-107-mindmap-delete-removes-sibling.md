## 背景

用户报告：在 xmind 文件中，顶层节点下有三个子节点，选中末尾（第三个）节点，按下键盘删除键（Delete/Backspace）后，**末尾节点和中间节点被一起删除了**（期望只删选中的末尾节点）。

## 现状（triage 核实）

删除键被**同一 `window` 上的两个 keydown 监听各处理了一次**，`REMOVE_NODE` 同一次按键同步执行两遍：

1. **应用层**（DEV-099 引入，binary-host 思维导图编辑器组件内）：`window.addEventListener('keydown', ...)`，在 `(e.key === 'Delete' || e.key === 'Backspace') && !mod` 分支里 `e.preventDefault()` 后 `mindMap.execCommand('REMOVE_NODE')`。注释明示这是 DEV-099 快捷键（Delete 删除选中、Ctrl/Cmd+Z 撤销、Ctrl/Cmd+Shift+Z 与 Ctrl+Y 重做、Ctrl/Cmd+S 立即保存）。
2. **库层**（simple-mind-map 0.14.0，应用以 ESM 直引其 `src/`）：`MindMap` 构造时 `keyCommand` 在**同一个 `window`** 上注册 keydown 监听；`Render` 里注册了 `'Del|Backspace'` 快捷键，同样执行 `execCommand('REMOVE_NODE')`。

两个监听都不检查 `e.defaultPrevented`，也没有 `stopImmediatePropagation` 或去抖——`preventDefault` 在同目标的多个监听器之间拦不住对方，`Command` 的 `addHistoryTime` 节流只节流历史记录、不节流命令执行。

**误删中间节点的机制**（库内 `Render.removeNode`）：

- 无参 `REMOVE_NODE` 删除 `activeNodeList` 全部节点；守卫只要求列表非空。
- 单选删除后，`deleteNodeActive` 选项（默认 `true`）让库**自动激活相邻兄弟**：`getNextActiveNode` 对末尾节点取的是**前一个**兄弟。于是第一次删除后 `activeNodeList = [中间节点]`（渲染是异步的，不干预本 tick）。
- 第二次 `REMOVE_NODE` 立即执行，守卫通过，把 `activeNodeList` 里的中间节点也删掉。
- 最终子节点 `[c1, c2, c3]` → `[c1]`，与用户现象完全吻合。

**为什么"点选节点后按删除键"必现**：库快捷键默认只在鼠标位于 SVG 画布内时生效；用户刚点选节点（鼠标在画布上、焦点落在 body，库对 body 目标放行），所以库监听必然触发。

**双重分发不止 Delete**：Ctrl/Cmd+Z / Ctrl+Y（撤销/重做）在应用层与库层（`Command` 的历史快捷键）同样各执行一次。撤销场景下双重执行通常是幂等的（回退两步 vs 回退一步的语义差异需要核实），但属同一缺陷类别。

**测试空白**：全仓没有"选中单个节点按删除键只删该节点"的测试；思维导图相关测试只覆盖 toolbar/menu 的 UI 态与布局管线，删除键链路零回归防护。

**结论：代码路径复核成立，双重分发确凿。**

## 期望行为

1. 选中任意单个节点按 Delete/Backspace，**只删除该节点（及其子树）**，相邻兄弟不受影响。
2. 删除后的焦点/激活行为与 simple-mind-map 单次删除语义一致（自动激活相邻兄弟本身是库的正常行为，但不得连带触发第二次删除）。
3. 撤销/重做快捷键（Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z、Ctrl+Y）每次按键只执行一步，不因双重分发产生步进异常。
4. 文本编辑态（contenteditable）、输入框内的删除键行为不变（现有守卫保留）。
5. Ctrl/Cmd+S 立即保存等库没有的能力保持不变。

## 关键接口

- 思维导图编辑器组件的 `window` keydown 监听：`Delete`/`Backspace` 分支与 `BACK`/`FORWARD` 分支需要与库的快捷键注册**二选一**——要么移除应用层与库重复的分发（保留库处理，应用层只留库没有的键如 Ctrl+S），要么移除库对 `'Del|Backspace'`（及撤销/重做）的注册、保留应用层。判定标准：**同一次按键事件，`REMOVE_NODE` / `BACK` / `FORWARD` 恰好执行一次**。
- 若保留双监听结构，至少一侧须在对方已处理时退出（`defaultPrevented` 检查 + `stopImmediatePropagation`，注意库监听先注册、先执行，`preventDefault` 单独拦不住先执行的监听）。
- 可选缓解（非根因）：构造 `MindMap` 时不启用"删除后激活相邻节点"选项，使第二次空删守卫直接返回——但这只是遮蔽症状，修复仍以消除双分发为准。
