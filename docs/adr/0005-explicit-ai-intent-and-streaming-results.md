# AI 请求必须由显式意图触发并以流式结果呈现

NexNote 的 AI 对话、AI 辅助写作及其他 AI 文本生成统一采用流式生成：首个片段到达即显示，用户可在生成中取消；已经显示的内容在取消、失败或断线后保留并标记为未完成。AI 对话的流式回复作为会话内容保留，AI 辅助写作则停留在临时 diff 中，只有用户 Accept 才写入页面，并以一次操作形成一个 undo 单元。

任何 AI provider 请求（包括 LLM 生成、embedding、自动分类与语义索引）都必须由用户的显式 AI/检索意图触发。输入、删除、粘贴、撤销/重做、光标或选区变化、自动保存、标题同步、Tab 切换、打开编辑器或对话 dock、预览、普通搜索与页面浏览均不得触发 provider 请求；这条不变量必须在请求层通过 mock provider 或 request spy 验证，而不能只检查界面是否出现 loading。

## Consequences

- 普通编辑链路与 AI/索引链路必须保持边界，未来新增后台索引不得偷偷挂接到编辑保存流程。
- 流式会话需要区分生成中、已完成、已取消和失败/断线等可见状态，并能在界面切换后继续处理已显示内容。
- AI 写作的预览与正式页面写回必须分离；Accept/Cancel 不能退化为逐 token 写盘。
