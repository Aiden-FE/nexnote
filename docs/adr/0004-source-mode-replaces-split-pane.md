# 以 Markdown 视图取代通用双 Pane 分屏

NexNote 原有的「分屏」是一个通用的第二 tab 栈：左右两个 Pane 可各自打开任意 tab，但两侧都是同一种块编辑器，没有任何功能依赖右 Pane（搜索、图谱、反链、AI、设置一律打开到当前激活 Pane），首启动却默认占用一半窗口，用户既看不出用途也得不到预览价值。决定**彻底移除通用双 Pane 分屏**（含 `splitEnabled`/`splitRatio` 布局字段、分隔线、⌘K「切换左右分屏」命令），改为按页面 tab 临时启用的**源码模式**：左侧以 CodeMirror 6 编辑 Markdown 原文，右侧复用编辑器内核以只读方式渲染**实时预览**；默认仍是块编辑模式，由用户主动切换。

## Considered Options

- **保留分屏并只改默认值**：成本最低，但留下一个无专属用途、易再次令人困惑的功能面，且与源码模式的并排布局在概念和 UI 上互相打架；否决。
- **两侧都可编辑的双向同步**：需要协调两套光标、选区、undo 栈与内容映射，显著增加同步复杂度；改为「源码是唯一真相 + 只读预览」的单向数据流。
- **源码模式状态持久化到页面或全局**：会让用户下次打开页面时莫名其妙看到源码，且需在 vault 配置存 per-page 状态；改为 tab 级临时状态，关闭 tab 即回到块编辑模式。
- **预览只做基础 Markdown 渲染**：Mermaid、KaTeX 与插件块不渲染会让预览失去一半价值；改为复用内核只读实例，完整富渲染。

## Consequences

- 源码模式下的保存**逐字节写回编辑框内容**，不做序列化规范化；只有切回块编辑模式再编辑后才会经 TipTap 重新序列化，可能统一列表标记等格式。
- 「首 H1 ↔ 文件名」绑定在两种模式下行为一致：在源码里改标题同样触发文件改名，避免同一功能出现两套规则。
- 源码模式不提供块编辑模式专属交互（块右键菜单、拖拽手柄、标题折叠），frontmatter 属性面板隐藏、YAML 以原文出现在编辑框中。快捷插入使用的 `/` 入口不属于块专属交互，统一遵循 ADR-0006；其他块级斜杠菜单动作仍不在源码模式范围内。
- 修订（2026-09）：应用户要求，源码模式提供划词工具栏与 AI 辅助——选区走 agent:run:writing（prompt 由主进程持有），Accept 以单个 CodeMirror 事务写回，不经块编辑器序列化，Markdown 原文语义不变；斜杠菜单/拖拽手柄等块编辑专属交互仍然排除。
- 修订（2026-09，划词按钮集统一）：源码模式划词工具栏从「仅 AI」扩展为与块编辑模式一致的按钮集——格式化五项（加粗/斜体/删除线/行内代码/链接，映射为 Markdown 语法包裹选区）、插入双链 `[[]]`、AI 写作与询问 AI；两种模式的按钮语义一一对应，格式化写回与 Accept 同为原文级编辑，不经块编辑器序列化。
- 修订（2026-09，DEV-025 Markdown 文档属性面板）：`format=markdown` 的文档在源码模式提供 FrontmatterPanel（表格 / YAML 双模式，与块编辑共用同一 FieldEditor 与字段目录），YAML 头从 CodeMirror 编辑框抽离、由面板承载并可双向写回；无 YAML 头的 `.md` 可经面板新增首个字段并在文件头生成 `---` 块。序列化仅发生在经面板实际编辑之后：未编辑的打开 → 保存往返文件字节不变（含 YAML 缩进、引号风格、CRLF/LF）；面板编辑只替换 YAML 头区域，分隔线风格、头部与正文间空行及正文字节不动（CRLF 文档写回 CRLF）；YAML 解析失败时复用 FrontmatterPanel 既有锁定语义——面板锁定在源码模式、保留原文，修复后才可切回表格。上文「frontmatter 属性面板隐藏、YAML 以原文出现在编辑框中」仅适用于 native-block 文档的**临时**源码模式（原文查看语义）。
- 修订（2026-09，文档属性按需 Popover）：为避免属性编辑器侵占页面编辑与 Markdown 实时预览区域，块文档与 `format=markdown` 文档统一只在编辑器顶部状态栏显示轻量「属性」入口；面板默认关闭，点击后以顶部锚定、内部可滚动的 Popover 展开，支持按钮再次点击、Escape 与点击外部关闭。Popover 打开/关闭不改变正文或预览布局；Markdown YAML 始终从 CodeMirror 正文抽离，无 YAML 与损坏 YAML 仍保留入口及既有生成/锁定语义；右侧只读属性 dock 不变。
- 修订（2026-09-16，Markdown 三视图与分栏调整）：`format=markdown` 文档的「源码模式」拆分为三种互斥的 **Markdown 视图**——源码视图（仅源码编辑）、分栏视图（源码编辑 + 实时预览）、预览视图（仅只读富渲染），术语见 CONTEXT.md；「源码模式」一词此后仅指 native-block 文档经 Mod+E 临时进入的原文查看形态。分栏视图的分割线可拖拽：复用侧栏同款 Resizer（pointer capture + `role="separator"`），拖拽时两侧实时重排；保存相对比例、任一侧最小 20%，双击恢复 50/50；方向键每次 2%、Shift+方向键每次 10%。比例仅在当前 tab 生命周期内保留——跨视图切换保留、关闭 tab 丢弃、新 tab 默认 50/50，不写入 vault。
- 修订（2026-09-16，预览视图边界）：预览视图隐藏 CodeMirror 编辑器、编辑器工具栏的编辑动作、文档属性入口及其 Popover、划词工具栏、AI 写作与翻译浮层、光标与快捷插入；工具栏原位常驻仅含三态切换的**视图切换器**。保留应用外壳（tab 栏、侧栏、Chat Dock）、文本选择与复制、滚动、Mermaid/KaTeX/插件块、查找等非编辑能力；双链与内部链接在同一 tab 内导航且保持预览视图（预览视图无未保存编辑，导航不涉及 flush，目标文档以最后保存内容渲染），外部链接沿用 openExternal。进入预览前 flush 当前编辑，保存失败则停留编辑视图；CodeMirror 实例、光标位置与 undo 栈在 tab 内保留但不挂载，返回编辑视图时恢复；预览视图复用实时预览组件与样式、占满内容区，不做独立阅读排版。新开 markdown tab 默认进入分栏视图。快捷键 Mod+E 语义为「源码 ↔ 分栏」，新增默认绑定 Mod+Shift+E 为「预览 ↔ 最近编辑视图」（可在设置中改绑）；命令面板提供三条视图命令；工具栏三态入口在窄窗口整体折叠进溢出菜单。
- 修订（2026-09-17，DEV-047 悬浮目录入口）：预览视图工具栏在视图切换器之外增加「悬浮目录」开关。该入口属于标题导航（依据 ADR-0012，悬浮目录为 tab 生命周期临时 UI），不是编辑动作，也不改变预览视图的只读边界；上文「仅含三态切换的视图切换器」据此放宽为「视图切换器 + 导航类悬浮目录开关」。
- 验收边界（2026-09-16 追加）：预览视图不得残留任何编辑态（无光标、无划词、无属性编辑入口）；三视图往返不改变文件字节；分栏比例需覆盖 clamp 下限、双击重置、键盘调整、tab 内跨视图保留与关闭丢弃；预览视图内导航保持预览视图，其他入口新开 tab 默认分栏。
- 滚动同步为源码 → 预览单向跟随；预览内双链与链接可点击，并在同一 tab 内导航且保持源码模式。
- 修订（2026-09-17，DEV 折叠与快捷输入轮）：上文「源码模式不提供……标题折叠」「其他块级斜杠菜单动作仍不在源码模式范围内」按文档格式区分：`format=markdown` 文档的源码视图与分栏视图编辑侧获得标题章节折叠（ADR-0013，临时视图状态、gutter 入口、不写正文）与完整 `/` 快捷输入菜单（ADR-0006，含块类型转换动作）；拖拽手柄、块右键菜单等依赖 TipTap 结构的交互仍仅在块编辑模式提供。native-block 文档临时源码模式（原文查看语义）维持原边界，不新增折叠与斜杠菜单。
- 旧 vault 配置中遗留的 `splitEnabled`/`splitRatio` 不做迁移代码：类型移除后读取自然忽略，下次布局写回时整体覆盖而消失。
- 引入 CodeMirror 6 作为源码编辑器依赖，同时为设置中尚未接线的 `vimMode` 留出后续落地路径。

## 实施默认值与验收边界

以下为本轮补齐的实施默认值，区别于上文用户已确认的产品决策；不代表功能已经实现或验收通过。

- 解析或渲染失败不得阻断源码编辑与原文保存。局部 Mermaid、公式或插件渲染错误在对应预览位置展示，不将普通未闭合 Markdown 当作整页解析失败。整页解析失败时显示明确错误；若保留上次预览，须标明其已过期。
- 预览采用约 200ms debounce，复用实例而非每次输入重建编辑器；异步结果只允许最新版本生效。源码滚动单向驱动预览，用户在预览滚动不反向移动源码。
- 模式切换前 flush 当前编辑内容；保存失败或切回块编辑模式时整页解析失败，应停留原模式并保留内容。仅切换模式不得触发原文规范化写盘。
- 预览中的内部页面链接在保存成功后于同一 tab 导航，保留源码模式；保存失败则取消导航。外部 URL 不作为 vault 页面加载，沿用应用现有安全打开策略，不因源码模式放宽协议限制。
- CodeMirror 与块编辑器各自维护 undo/redo，不承诺跨模式撤销；模式切换后的撤销不能恢复另一页面内容或覆盖已保存原文。
- 外部文件变化遇到本地未保存源码时，不自动覆盖任一版本；暂停冲突路径的自动保存，保留本地缓冲区并提示用户选择处理方式。无本地修改时可重新载入。实现需检查写入前版本，而不能仅依赖延迟到达的文件监听事件。
- 原文保真验收覆盖 YAML、尾随空行、列表标记、代码围栏及 CRLF/LF；无编辑的打开、保存与模式往返必须不改变文件。源码编辑器内部换行模型不能成为无意规范化的理由。
- 验收同时覆盖旧配置含 split 字段仍只有一个 tab 栈、三种切换入口、tab 关闭后模式重置、完整富内容只读预览、H1 改名后的树与 tab 同步、保存失败、快速输入与导航、外部修改冲突。未实际执行的 GUI 或平台验收标记为 `NOT_RUN`。
