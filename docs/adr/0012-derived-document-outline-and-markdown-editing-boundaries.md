# 目录采用派生模型并保持 Markdown 原文边界

## Context

当前页面需要同时支持标题导航、可写入正文的目录占位和临时悬浮导航，但三者的持久化语义不同。若把目录条目或自动生成的标题锚点写回页面，标题变化会制造无关 diff、失效链接和格式漂移；若为了这些能力重新序列化 Markdown，则会破坏源码视图既有的原文保真承诺。图表快捷插入也需要与其他 Markdown 工具共享可移植的落盘格式。

## Decision

- **标题目录采用派生模型**：标题条目由当前页面标题实时派生，不作为第二份页面结构持久化。Markdown 页面以源码位置定位标题，块页面以块位置定位标题；标题变化后重新派生位置。
- **正文目录只持久化意图**：正文目录块写盘时仅保存 `<!-- nexnote:toc -->`，展示条目由当前标题目录派生。标记本身参与普通编辑、保存和撤销，不保存条目快照。
- **悬浮目录是临时 UI**：悬浮目录复用同一标题目录，只存在于所属 tab 或组件生命周期，不写入页面、frontmatter 或知识库配置。
- **不生成隐式标题锚点**：目录导航使用派生的源码位置或块位置，不因展示、导航或保存目录而向标题注入 slug、块 ID 或 HTML anchor。用户已有的显式锚点保持原义。
- **Markdown 原文优先**：无编辑的打开、目录派生、目录导航和视图往返不得改写原文。Markdown 轻量格式化仅在用户显式触发时执行保守、语义不变的局部整理，不借机做全量序列化或无关规范化。
- **撤销历史彼此独立**：源码编辑器与块编辑器各自维护 undo/redo 栈，不承诺跨编辑形态撤销；正文目录标记、轻量格式化和图表插入进入发起编辑器自己的撤销历史。
- **Mermaid 使用标准 fence**：图表快捷插入产生标准的 fenced code block，以 `mermaid` 作为 info string；流程图、甘特图等仅是可编辑源码模板，不引入 NexNote 私有持久化格式。

## Consequences

- 同一派生模型可服务正文目录块与悬浮目录，同时避免目录条目与标题正文双写后失同步。
- 重名、空标题或标题移动不要求修改正文；运行时标识只服务本次呈现，不能被当作稳定的跨会话链接契约。
- 源码定位与块定位必须分别覆盖标题增删、重排和跳级，并确保导航不会误落到代码围栏、frontmatter 等伪标题。
- 显式格式化可能产生可见 diff，但 diff 必须限定在用户选择的格式化范围；普通查看、导航与保存继续保持 Markdown 原文。
- 标准 `mermaid` fence 可被其他 Markdown 工具识别，但 NexNote 特有的模板入口和编辑体验不会随文件一同导出。
- 在源码与块编辑形态间切换后，用户不能依赖另一形态的 undo 栈恢复内容；切换和保存边界必须避免旧历史覆盖当前原文。

## Alternatives

- **持久化完整目录链接列表**：标题修改后需要持续重写目录，容易产生陈旧条目与噪声 diff；否决。
- **为每个标题自动写入稳定锚点**：可提供跨会话标识，但会把导航实现泄漏进用户正文，并与既有块锚点及原文保真冲突；否决。
- **悬浮目录状态写入页面或知识库配置**：会把短生命周期 UI 偏好变成可同步内容或全局状态；否决。
- **借助 Markdown 全量序列化实现格式化**：实现统一但会改写列表、围栏、空行和换行风格等无关内容；否决。
- **跨源码与块编辑器共享 undo 栈**：需要在两种位置模型和序列化边界间映射历史，失败时可能覆盖已保存原文；否决。
- **以私有 Mermaid 块语法保存图表**：可携带 NexNote 元数据，但降低与通用 Markdown/Obsidian 工具的互操作性；否决。
