# 翻译入口与无思考 AI 请求

本 ADR 把翻译能力的入口与请求约束沉淀下来，避免未来无意中把临时翻译退化为自动写回，或把翻译请求退化为带思考 token 的成本敏感调用。

## Decision

1. **三种翻译入口并存**，各自只读、不落盘、不写回页面或知识库：
   - **划词翻译**：在块编辑器与 Markdown 源码/分栏视图中通过选区触发，沿用现有 `translate:selection` 流程；
   - **全文翻译**：通过编辑器工具栏的「全文翻译」动作触发，仅作用于当前页面正文，沿用现有 `translate:document` 流程；
   - **输入翻译工作台**：通过命令面板与划词工具栏的 AI 下拉入口打开一个独立面板，用户输入任意原文并获取译文；首次实现时同时支持命令面板与划词工具栏 AI 下拉两个入口。
2. **预览视图不暴露翻译入口**。预览视图属于只读呈现态，工具栏仅承担视图切换，全文翻译触发仍需在编辑或源码上下文中进行，避免在只读视图里制造 AI 触发点。
3. **结果呈现在临时翻译层**（参见 `CONTEXT.md` 的「临时翻译」），结果只读可复制，关闭即丢弃，不写回、不落盘、不产生 Git 变更；这一边界与 ADR-0005 的显式意图共同作用。
4. **目标语言**采用「全局默认 + 触发点临时切换」：在 AI 设置中提供翻译的全局目标语言默认值；翻译触发点上保留当次切换的 UI 选项，覆盖默认但不持久化。
5. **源语言自动检测**，不向用户要求；高级显式指定作为后续扩展。
6. **所有翻译请求统一为无思考 AI 请求**：在协议参数层显式关闭模型思考/推理能力，并对流式与最终响应做 `<think>` / `<analysis>` 残留清洗。具体而言：
   - 当前已支持的 OpenAI-compatible（含 Azure）chat completions 路径必须映射 `reasoningEffort: 'none'` 到请求体的 `reasoning_effort` 字段，且翻译路径覆盖任何来源的 per-request 覆盖值；
   - 协议实现或适配器扩展到 Anthropic / Ollama / OpenAI Responses 时，需同步补齐对应协议的思考关闭参数（如 `thinking: { type: 'disabled' }`、`think: false`、`reasoning: { effort: 'none' }`），不允许出现「该协议默许思考」的接入路径；
   - 输出层（流式片段与完整响应）必须经过 `sanitizeReasoningArtifacts` 清洗，确保未配置关闭参数或供应商额外返回思考内容时仍能产出干净译文。
7. **复用 AI 供应商适配器**：翻译请求从用户已配置的供应商 profile 中选取，不为翻译独立维护供应商配置；可在 AI 设置中提供「翻译使用哪个 profile」的选择器，并记忆上次选择。
8. **共享 200k 字符上限**：划词、全文、工作台统一限制单次翻译请求的输入长度；超过时明确报错，输入工作台提供剩余额度提示，不截断不静默失败。

## Considered Options

- **让翻译结果写回页面（替换选区 / 新建译文页 / 双语对照）**：保留为后续扩展。首期只做只读结果，避免与显式 AI 意图冲突，也避免把临时翻译概念与正式文档编辑混淆。
- **为翻译单独维护供应商配置**：与现有 profile 体系重复建模；改为复用 profile 并提供选择器。
- **用低 temperature 或提示词约束代替显式思考关闭**：拒绝。temperature 不影响思考 token，提示词无法验证；显式参数 + 输出清洗才是可验证约束。
- **在协议未支持思考关闭时跳过该协议**：拒绝。NexNote 当前已支持 OpenAI-compatible，未支持协议的接入必须以「带显式思考关闭参数」为前置条件。

## Consequences

- 翻译触发点不再扩散到只读视图，预览视图工具栏维持极简。
- 翻译的实现需要复用 `AgentGateway.run(scenario: 'translation', ...)` 与现有 `TRANSLATION_REASONING_EFFORT='none'` 约束；工作台作为 renderer 侧的入口，需要新增 IPC 与场景编排，但不应引入新的 AI scenario。
- 协议扩展（Anthropic / Ollama / OpenAI Responses）的接入测试需要包含「翻译路径显式思考关闭」与「输出清洗」的断言。
- 输入长度上限统一为 200k 字符后，UI 需要在工作台入口提供剩余额度提示，避免用户在大段粘贴时遭遇静默失败。
- 输出清洗使翻译结果在多供应商场景下具有一致性，并降低用户对「模型偷偷思考」的疑虑；这也是验收时必须覆盖的端到端检查项。
