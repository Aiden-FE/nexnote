# 欢迎页「快速上手」跳转官网文档，应用内引导保留为离线入口

欢迎页的「快速上手」此前只调用 `setTourOpen(true)`，打开 5 步应用内界面聚光灯引导（页面树、两种编辑模式、AI Dock、版本时间线、设置），应用内此前**没有任何**指向官网或文档的链接。新文档体系（ADR-0021）落地后，决定让欢迎页「快速上手」按钮**改为在系统默认浏览器中打开官网文档快速上手页**，链接语言跟随当前界面语言（zh-CN → `/zh/docs/getting-started`，en-US → `/docs/getting-started`）。应用内引导不删除：首次打开知识库仍自动弹出，设置页「帮助 → 新手引导 → 重新播放」仍可回放。设置页「帮助」区同时新增一行「产品文档」入口。

打开外部 URL 复用主进程既有 `setWindowOpenHandler` 通道（`https?` → `shell.openExternal`，新窗口一律 deny），渲染层以 `window.open` 触发，**不新增 IPC 通道**。官网地址取仓库既有的 `homepage`（ADR-0010 约定的生产 URL），不硬编码第二个域名。

## Considered Options

- **保留引导按钮、另加一个文档按钮**：两个并排动作会让欢迎页的「聚焦入口」定位变模糊；否决，主按钮改指文档，引导退居设置页与自动弹出。
- **先跑完引导、末尾再给文档链接**：保留离线路径，但把一次 5 步点击放在「想看文档」之前，延长了最直接的路径；否决。
- **新增 `app:openExternal` IPC 通道**：功能上可行，但 `window.open` 已能可靠命中主进程守卫，且新增通道需要走契约白名单与 preload 暴露，无收益地扩大攻击面；否决。
- **应用内 WebView 打开文档**：把外部网页嵌进沙箱渲染层，破坏「渲染层只渲染自身 origin」的边界；否决。

## Consequences

- 文档链接要求联网；离线用户仍有引导与设置页重播覆盖首次上手场景，但覆盖内容不等同于完整文档。
- 欢迎页测试需改写：`welcome-page.test.tsx` 现仅断言文案不受影响，`guided-tour.test.tsx` 中断言 `welcome-start-tour` 打开引导的用例必须改为断言打开外部链接。
- 链接语言依赖界面语言真实生效（ADR-0023），在界面语言仅是假开关期间，文档链接须先以固定语言或界面语言的当前可信值落地，不得假设语言切换已可用。
