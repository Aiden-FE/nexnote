# ADR-0019 手机端数据与能力本地化

- 状态：accepted
- 日期：2026-09-30
- 关联：ADR-0017、ADR-0018

## 背景

ADR-0018 确立手机端完全独立（不经桌面端中转）后，AI、搜索与本地存储必须在手机端自行落地。三项在桌面端都有既有实现：AI 密钥存 OS 钥匙串、搜索走 FTS5 派生索引（桌面分词为 CJK unigram+bigram + 拉丁前缀）、vault 位于本地目录。

## Decision

- **AI**：手机端独立配置供应商 Profile，密钥存 iOS Keychain（经 `SecretVault` 抽象替换实现）；v1 会话固定「对话（只读）」权限模式，不产生编辑提案与写回；检索 Skill 与 Agent 工具不进手机端。
- **搜索**：手机端在设备上重建 FTS5 派生索引，分词语义与桌面端一致；向量召回 v1 不做，AI 召回退化为关键词 + 标签 + 双链扩展两阶段。
- **存储**：设备知识库放在 `Library/Application Support` 子目录并标记排除 iCloud 备份；因未推送提交在设备上是唯一副本，启动时须提示未推送状态。

## Considered Options

- **AI 借道桌面端代理**：与完全独立定位冲突，否决。
- **桌面端提供 HTTP/WS API**：伴生模式的变体，同上否决。
- **v1 不做搜索**：中文全文搜索是刚需，否决。
- **Documents 目录**：随 iCloud 备份/同步整个 `.git`，等于把文件级同步的已知坏路引入设备端，否决。
- **Caches 目录**：可能被系统清理，未推送提交会丢，否决。
- **手机端向量召回**：embedding 成本高、边际收益低，延后。

## Consequences

- 桌面端零改动，跨端只共享行为语义（分词规则、元数据头约定、提交消息前缀），不共享代码。
- 搜索一致性依赖两端分词实现对齐，必须作为该里程碑的验收项。
- 手机端 AI 权限模式是固定值而非可切换项，与桌面三档权限模式是两套入口。
- AI 依赖网络（远程供应商），离线时不可用；离线编辑不受影响——本地提交由设备端 Git 保证。
