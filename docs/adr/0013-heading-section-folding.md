# 标题章节折叠是临时编辑视图状态

块编辑模式与 Markdown 编辑视图都支持按标题章节折叠。标题章节从一个标题之后开始，到下一个同级或更高级标题之前结束，包含其下属的低级标题及内容；折叠标题时隐藏整个标题章节，但标题自身保持可见。

折叠是编辑视图状态，不是页面正文或共享元数据。它不得改写 Markdown、TipTap 内容或 sidecar，重新打开页面时全部展开。Markdown 的折叠只作用于源码视图及分栏视图的 CodeMirror 编辑侧；分栏右侧实时预览和预览视图始终展示完整页面，不跟随源码折叠。

H1–H6 左侧提供低视觉权重的 disclosure chevron：展开态与折叠态可辨，hover 或 keyboard focus 时增强；没有章节内容的标题不提供可操作箭头。块编辑模式在标题左侧呈现控件，同时保留块菜单中的“折叠/展开”文字入口；Markdown 在 CodeMirror gutter 中呈现，不向源码字符区写入标记。折叠状态允许嵌套：父章节展开后，先前单独折叠的子章节仍保持折叠。

标题折叠只影响视觉呈现，不改变完整文档语义。保存、导出、全文搜索、全文翻译和全文 AI 上下文仍包含折叠内容，`Mod+A` 仍以完整文档为范围；编辑器查找命中隐藏内容时，应展开定位该命中所必需的祖先章节。鼠标只在可见区域拖选时不得意外选择隐藏内容。键盘光标导航不进入隐藏内容，从折叠标题向下移动时跳到章节边界后的下一个可见位置；只有显式展开、查找命中或跳转到隐藏锚点时才自动展开必要的祖先章节。

删除标题或将其转换为非标题块时立即丢弃对应折叠状态，Undo 恢复标题时默认展开。标题仍能可靠对应但层级发生变化时保留折叠状态，并按新层级立即重新计算章节边界；无法可靠对应时安全回退为展开，不得折叠错误章节。空标题、重复标题与改名标题均可独立折叠，折叠身份不得依赖可见文本或 slug。

Markdown 首期折叠范围覆盖 ATX H1–H6 与 Setext H1/H2。blockquote 内标题仍作为标题目录条目参与导航，但首期不提供折叠，避免错误跨越引用边界。悬浮目录跳转到被折叠祖先遮蔽的标题时，自动展开所有必要祖先并定位、高亮目标；目标标题自身若已折叠则保持折叠。

提供“全部展开”命令，入口位于标题目录菜单与命令面板；本轮不提供无差别“全部折叠”。若未来增加批量折叠，应采用“折叠到 H1/H2/H3 层级”的明确语义。


- 修订（2026-09-19，DEV-061 统一块编辑器左侧 gutter）：块编辑模式折叠控件从标题内部 ProseMirror widget 迁移为宿主级 overlay（位于 `.nexnote-editor-host` 内），与拖拽手柄共享统一的 3.75rem 双列 gutter：手柄列 1.6rem + chevron 列 1.6rem + 0.5rem 列间距。标题不再为 chevron 预留 `padding-left`，多行标题折行顶到内容左缘。拖拽手柄移除 `translateX(-1.9rem)` hack，改用 `@floating-ui/dom` `offset` middleware（mainAxis = gutter - 手柄列宽 ≈ 2.15rem）参与布局计算；拖拽手柄增加透明 `.nexnote-drag-handle__bridge` 桥接元素，鼠标从正文移到 gutter 不再触发 TipTap `mouseleave` 隐藏。Markdown 源码（DEV-055）的 CodeMirror gutter 折叠与本决策独立，按既有 contract 保持不变。验收边界同步更新：chevron 常显、可键盘承接焦点、与拖拽手柄对齐成稳定双列；窄分栏下手柄/chevron 不被滚动容器裁剪。

## Considered Options

- **把折叠写入正文**：会污染用户原文并影响其他 Markdown 工具，否决。
- **把折叠写入 sidecar 并跨会话恢复**：需要解决标题改名、移动、重名以及两种编辑模型的稳定身份映射；当前收益不足，否决，重新打开统一展开。
- **让实时预览跟随源码折叠**：容易让用户误以为章节已删除，并造成屏幕呈现与导出、打印不一致；否决。
- **只从块菜单触发**：首次使用不易发现；改为标题旁 disclosure chevron，并保留文字菜单作为替代入口。
- **展开父章节时清空全部子折叠**：破坏用户已经建立的局部阅读状态；改为保留嵌套状态。

## Consequences

- 块编辑与 Markdown 编辑必须共享相同的标题章节边界语义，但分别适配 ProseMirror 顶层标题节点与 CodeMirror Markdown 标题范围。
- Markdown 原文保真边界不变；折叠不得成为序列化或规范化 Markdown 的理由。
- 折叠控件必须可通过键盘操作，具有可辨的展开状态、准确的 accessible name，并纳入 Tooltip 与 focus-visible 规则。
- 查找、选区、复制与隐藏 DOM/Decoration 的实现必须验证不会把临时视觉隐藏误当成内容删除。
- 验收必须覆盖：同级与高层级边界、嵌套折叠、标题删除与类型转换、标题升降级、空标题与同名标题、目录跳转自动展开祖先、键盘跳过隐藏内容、重新打开全部展开，以及 Markdown 折叠前后文件字节不变。
