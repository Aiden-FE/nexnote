NexNote 把你的每次修改都沉淀成 Git 历史。这一章解释提交是怎么产生的、如何回看历史，以及遇到同步冲突时的处理原则。

## 自动提交与手动提交

内容先**自动保存**到磁盘（默认停止输入 1.5 秒后），随后进入**自动提交**窗口：把这段时间内的所有改动打包成一次 Git 提交，默认 30 秒一次。你也可以随时在命令面板（⌘K）里手动提交，并自己写提交说明。

| 提交类型 | 触发 | 说明 |
| --- | --- | --- |
| 自动提交 | 防抖窗口到期 | 提交说明由应用生成 |
| 手动提交 | 命令面板 | 你写提交说明 |

两个间隔在不同分区调整：**自动保存**间隔在 **设置 → 编辑器**，**自动提交**间隔在 **设置 → Git**。

## 版本时间线

每个页面都有版本时间线，按时间列出与该页相关的提交。你可以：

- 查看任意一次提交改了什么；
- 把页面恢复到某个历史版本。

时间线读取的是仓库真实的 Git 提交，所以它和你在命令行里看到的历史完全一致。

## 同步冲突

当本地与远程都有改动、无法自动合并时，NexNote 会**阻塞写入**而不是替你做合并。这是刻意的：冲突内容不会在你不知情的情况下被覆盖。

底部状态栏会出现冲突徽标，点击它会打开「同步医生」：

1. 它先给出**诊断**（冲突类型、涉及文件、当前分支状态）；
2. 再给出**修复方案**，并展示将要执行的命令预览；
3. 涉及破坏性操作（如中止 rebase）时会要求你确认。

修复方案里的命令都来自 Git 本身，应用只负责诊断和编排，不会在你没有确认的情况下改写历史。

## 几种常见状况

| 诊断类型 | 含义 | 典型处理 |
| --- | --- | --- |
| `conflict` | 文件内容冲突 | 打开同步医生，按引导解决 |
| `non-fast-forward` | 远程有你本地没有的提交 | 先拉取再推送 |
| `no-remote` | 知识库未配置远程 | 配置远程仓库 |
| `auth` / `network` | 凭据或网络问题 | 检查凭据与网络后重试 |

## Git 不只是同步工具

即使你从不同步到任何远程，本地 Git 历史依然成立：它让「版本时间线」「恢复历史版本」这些能力在单机上就可用。远程同步是可选项，不是使用前提。
