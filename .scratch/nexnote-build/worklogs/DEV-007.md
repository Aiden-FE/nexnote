# DEV-007 · Git 底座：自动提交与版本时间线

## 实施摘要

- 新增主进程 `GitService`（`simple-git`）：默认优先解析 `dugite` 嵌入式 Git；设置可显式切换系统 Git。保留系统 `~/.gitconfig`、`SSH_AUTH_SOCK` 与凭证环境，供 SSH agent / Keychain / GCM 使用。
- 新建 vault 时自动 `git init`、按 ADR 0003 写入 `.gitignore`（整体忽略 `.nexnote/` 运行时目录，仅 allowlist `.nexnote/config.json` 与 `.nexnote/layout.json`）并生成初始提交。
- `fs:writeTextFile` 会触发默认 30 秒防抖自动提交，含 `nexnote:auto:` 机器可读前缀、可读摘要和最短间隔节流。支持 `nexnote:manual:` 手动提交和 `nexnote:restore:` 文件恢复提交。
- 建立完整 `git:*` IPC 契约与 handler：状态、时间线、自动/手动提交、远程预检与管理、pull/push、文件历史与恢复预览、克隆、Git 选择开关。
- 远程绑定会先执行 `git ls-remote --heads`；失败返回明确的 SSH/HTTPS/网络修复提示。pull 冲突被归类为 `MERGE_CONFLICT` 并提示在仓库目录手动解决。
- 渲染端经注册表新增 Git 状态栏（分支、变更数、ahead/behind、pull/push、刷新）和 Dock 版本时间线（HEAD、作者、时间、hash、自动/手动类型；手动提交输入支持 ⌘S）。首启动向导的“克隆远程仓库”已可用。

## 设计

数据流：渲染层 `invoke` → shared IPC 契约 → main `git-handlers` → `GitService` → simple-git/dugite。Git 操作只位于主进程；所有 Git 仓库测试均创建在 `os.tmpdir()`，从未对宿主仓库进行 Git 测试操作。

## 两轴 Review 阻塞修复（2026-09-06）

- **Vault 生命周期隔离**：`vault:close` 先执行 `git.setRoot(null)`，确保防抖计时器取消；关闭后发送空仓库 `git:statusChanged`。恢复、新建、打开、显式初始化时均切换 root 并推送实时状态。
- **显式初始化流程**：`vault:open` 对非 Git 目录只返回 `GIT_INITIALIZATION_REQUIRED`；向导展示目录、影响说明、确认/取消按钮。只有用户确认后才调用 `vault:initGit({ path })`，执行目录校验 → `git init`/初始提交 → 打开 vault。
- **实时状态事件**：`GitService.onStatusChanged` 覆盖初始化、自动/手动提交、remote 增改及预检失败、pull/push 成功或失败、clone、文件恢复；文件写入、创建目录、重命名、删除还会先发送即时 dirty 状态，自动提交完成后再发送 clean 状态。
- **完整 Git 产品面**：状态栏 pull/push 增加二次确认；时间线支持 vault 相对路径筛选单篇历史、按小时折叠连续自动提交、手动提交高亮、HEAD；remote 表单支持添加与点击回填编辑；文件恢复先展示 `- 当前/+ 目标` 行级差异，再二次确认并创建恢复提交。
- **Git 设置持久化**：侧栏“设置”已可打开 Git 设置界面；“使用系统 Git”默认关闭，写入 `nexnote-app.json`，主进程启动时恢复。时间线的 Git 设置区也提供同一控制。
- **现代 Git pull 行为**：pull 固定使用 `--no-rebase`，避免分叉时仅报 “Need to specify how to reconcile divergent branches”；真实内容冲突统一映射为 `MERGE_CONFLICT` 并给出手动修复提示。
