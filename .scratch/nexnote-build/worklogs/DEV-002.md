按已确认的 TipTap 3 + `@tiptap/markdown` 路线交付编辑器内核与渲染层集成：

### packages/kernel（新增）
- `extensions/`：StarterKit 子集 + TaskList/TaskItem（来自 `@tiptap/extension-list`）+ KernelCodeBlock（CodeBlockLowlight + ^id 末行追加）+ KernelTable（@tiptap/extension-table + 表行末锚点剥离 + 前导 \n 归一）+ KernelCodeBlock/Table 的 blockId 全局属性 + 自定义 `Callout`（27 个类型）/ `Wikilink`（含别名+子引用）/ `Hashtag`（Unicode 字母数字下划线连字符斜杠，禁 mid-word）/ `Frontmatter` 节点 + 拆装工具 + `SlashMenu`（@tiptap/suggestion + 框架无关 DOM 弹层）+ `createKernelDragHandle`（@tiptap/extension-drag-handle）。
- `markdown/`：在 @tiptap/markdown 之上叠加 Obsidian 方言管道
  - `block-id.ts`：`^id` 双向变换（行尾锚点 ↔ blockId 属性）—— 解析前 PUA 占位符替换（跳过围栏代码块），解析后 JSON 遍历把占位符提升为 `paragraph`/`heading`/`listItem`/`codeBlock`/`table` 的 blockId；序列化前反向注入，输出后还原为 `^id`；前后状态机对连续 standalone 锚点有确定性降级。
  - `pipeline.ts`：frontmatter 拆装、code 围栏自适应修复（利用 doc 知识定位上游单反引号坑点）、serialize 末尾前导 / 尾部换行归一、表格分隔行的 `-{3,}` 长度归一。
- `editor.ts`：`createEditor` 工厂（DOM 容器 + 配置 → 内核实例）、保存防抖（默认 500ms）内置、`moveBlock(blockId, targetBlockId, side)` 可测试事务入口、`flushPendingSave()`、`getFirstHeading()`、`getFrontmatter()`、`getRevision()` 协作预留。
- `save.ts`：`createSaveScheduler`（schedule/flush/cancel/hasPending + 重入保护）。
- `version.ts`：`KERNEL_VERSION = '0.1.0'`。
- 依赖：`@tiptap/core @tiptap/pm @tiptap/starter-kit @tiptap/markdown @tiptap/extension-unique-id @tiptap/extension-drag-handle @tiptap/extension-list @tiptap/extension-table @tiptap/extension-code-block-lowlight @tiptap/extension-image marked lowlight` + dev `happy-dom`。

## 已知限制 / 后续接入点

- **行内代码内含反引号的围栏长度**：`@tiptap/markdown` 的 mark 序列化通过占位符探测法生成 `\`...\`\`` 单一围栏（占位文本里查不到反引号）。内核在管道末用 doc 知识（收集含反引号的 code 文本）回查并重围（CommonMark 规则）。语义已 100% round-trip；该修复属于后处理，建议在后续 `npmmirror` 升级或转用 Milkdown 时观察上游是否补上。
- **混排任务/普通列表的块间距**：上游 `MarkdownManager.parseListToken` 把混排拆为多个列表节点，doc 级分隔符在中间多输出空行。`normalizeForCompare` 已做 `\n{3,}\n\n` 压缩，规范化比较视为等价。语义 JSON 完全稳定。
- **HTML 行内穿透**：`a <b>bold</b> c` 会经上游 `escapeMarkdownSyntax` 序列化为 `&lt;b&gt;...&lt;/b&gt;`，再解析回原文。语义稳定，但用户输入的 `data-*` 等自定义 HTML 不会以 HTML 形式保留——可视为「文档是 markdown」的设计取舍；如需保留 HTML passthrough 可由 DEV-017 决定扩展。
- **斜杠菜单 / 拖拽手柄的视觉层**：内核只提供 DOM 结构与行为，外观通过 `.nexnote-slash-menu` / `.nexnote-drag-handle` 全在渲染层 CSS 完成；可由后续设计/品牌票替换图标与定位。
- **block ID 全节点**：`UniqueID.configure({ types: ['paragraph','heading','listItem','codeBlock','table'] })` 会在编辑过程中给所有新块分配 blockId 并写回 `^id`，导致纯文本文件也带 `^id` 后缀。Obsidian 解析保留 `^id` 不会丢失信息；DEV-004 关系索引依赖此。若需要"按需分配"模式（仅在用户主动复制块链接时分配），由 DEV-004 在 UniqueID 上增加 conditionalUpdate 配置。
- **drag-and-drop E2E**：jsdom 无布局，`posAtCoords` 失效，因此拖拽只在真实 Electron 渲染层用 PM 的 `view.dragging` API 工作；smoke 用 `moveBlock` 等价事务作为业务级验证（save → reopen 顺序一致），拖拽交互可视化由 DEV-017 跟进。
- **行内代码 mark 共享 StarterKit 内置实现**：未自定义 Code mark（先前尝试用扩展动态围栏失败，因 mark 围栏静态探测），依赖 `fixInlineCodeFences` 后处理；常见用法覆盖 100%。
