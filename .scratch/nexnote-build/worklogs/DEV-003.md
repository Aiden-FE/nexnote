### 2. main 文件操作内核（`feat(main): page ops kernel`）
- `fs-service.ts`：rename 改为「目标存在拒绝」（POSIX rename 原行为是静默覆盖，会丢数据）；新增 `listTree` 扁平枚举；统一导出 `EXCLUDED_DIRS`（`.nexnote/.git/.trash/node_modules`）
- `fs/page-ops.ts`（新）：
  - `createNote`：自动 .md 后缀、自动「未命名 N」命名、`created` + `id`（UUID v4）默认 frontmatter
  - `rewriteWikilinks` 纯函数：basename 优先（保持最短形式），完整路径与目录前缀按前缀替换；处理 `[[a]]`、`[[a|别名]]`、`[[a#标题]]`、`[[a#^blockid]]`、`![[embed]]`、目录子树前缀
  - `renameWithLinks`：原子地做 rename + 全库 wikilink 扫描重写；目标已存在 / 目录移入自身子树 / 源不存在 / 相同路径均按明确错误码拒绝
  - `scanTags`：frontmatter `tags`/`tag` 块列表 + 行内数组 + 引号值；正文扫描内联 `#tag`（跳过围栏代码与行内代码，#^块引用与 # 标题不计入，# 前为文字字符时不计入）；按标签聚合文件列表
  - `splitFrontmatter` / `parseFrontmatterTags` / `extractInlineTags` 均为可单测纯函数
- `fs/watch-service.ts`（新）：chokidar 监听 vault 根，事件去抖后转发为 `fs:changed`；`sync()` 响应 vault 切换；`ready()` 门闩便于测试与启动时序；始终忽略 EXCLUDED_DIRS
- `VaultSession`：增加可选 `onChanged` 回调（不影响既有行为，dev/DEV-003 主进程入口接入 watcher）
- `ipc/fs-handlers.ts`：注册新通道；`fs:delete toTrash` 在 `shell.trashItem` 失败时回退到 vault 内 `.trash/`
- `IpcServices` 增加 `revealItem`（基于 `shell.showItemInFolder`）与 `watch: VaultWatchService`
- `ipc-registrar.test.ts` 假服务补全新字段

## 已知限制 / 后续接入点

- **wikilink 简单字符串替换**：多义性场景下可能误伤（如同名 basename 在不同目录同时存在时，移动其中一个会改写所有同名链接的 basename 形式）。DEV-004 关系索引完成后再升级为索引精确解析（ticket 写明「本票先做简单字符串替换」）。
- **大小写敏感**：macOS 文件系统大小写不敏感，Obsidian 链接解析也不严格大小写；本票按大小写敏感匹配以避免误改，DEV-004 索引驱动解析时再支持大小写不敏感。
- **标签聚合是全量重扫**：每次 fs:changed 防抖 600ms 后整体 `fs:scanTags`。在超大 vault 下需 DEV-004 索引驱动。
- **删除走 `shell.trashItem`**：依赖 Electron 内置 API（无 npm 依赖）；不可用时回退到 vault 内 `.trash/`，已是基础可用。
- **未实现编辑器**（DEV-002 并行中）：打开 .md 的 tab 内容为源码 + H1 标题，编辑器桥接为占位。
- **反向链接为占位**：UI 骨架 + 假数据，DEV-004 接入真实关系索引。
- **chokidar 5 的警告**：`"Stats" is imported from external module "node:fs" but never used` 是 chokidar 5 内部无静态分析警告，不影响功能。
- **拖拽移动的视觉反馈**：使用行背景高亮；与 Obsidian 风格接近，复杂动画留待后续 polish。
