## 方案与实现

### 1. 三平台 electron-builder

- `electron-builder.yml`
  - macOS: DMG + ZIP；Release CI 使用 arm64/x64 原生 runner 分别构建，防止 dugite Git 架构错配。
  - Windows: NSIS + portable x64。
  - Linux: AppImage + deb x64。
  - `asar: true` + `asarUnpack` 解包 `dugite` 二进制。
  - GitHub Releases provider，生成 `latest*.yml` 更新清单。
  - Markdown 文件关联和 `nexnote://` 协议。
- `dugite` 设为生产依赖；`pnpm.onlyBuiltDependencies` 允许其 postinstall 下载当前平台 Git。
- 验证过打包内 `app.asar.unpacked/node_modules/dugite/git/bin/git` 为 Mach-O arm64。
- 提供可复现占位图标 `build/icon.png` / `build/linux-icon.png` 与 `scripts/generate-icon.mjs`；正式品牌图标可原位替换。

### 2. 签名与公证

- hardened runtime + 主/继承 entitlements。
- 顶层 `afterSign: scripts/notarize.cjs`：只有 Apple ID 三项秘密齐全时调用 `@electron/notarize`；开发构建明确跳过而不伪称签名。
- Release workflow 将 macOS `.p12` 和 Windows `.pfx` base64 secret 临时写入 runner `$RUNNER_TEMP`，通过 `CSC_LINK` / `CSC_KEY_PASSWORD` 交给 electron-builder。
- Linux AppImage 使用可选 `LINUX_GPG_PRIVATE_KEY` 对产物做 detached armored signature。
- 无凭据 fork 不会获得秘密；仓库不包含任何证书或口令。

### 3. 自动更新

- `packages/main/src/updater.ts`：延迟加载 electron-updater，避免纯 Node 测试导入崩溃；支持 stable/beta/alpha、启动延迟检查、手动检查、手动/自动下载、进度事件、退出自动安装、显式重启安装。
- 默认使用 GitHub Releases；可用 `NEXNOTE_UPDATE_URL` 切换 generic 静态源并保持分通道路径。
- IPC：`checkForUpdates` / `downloadUpdate` / `installUpdate` / `setUpdateChannel` + `app:updateStatus` 推送事件。
- 设置扩展点：更新通道与自动下载策略持久化、检查/下载/重启安装按钮和下载进度。
- `updater.test.ts` 覆盖开发态、打包态通道设置、更新发现、下载进度、下载和安装约束。

### 4. CI/CD

- `.github/workflows/pr-check.yml`：PR/master 的 install/lint/typecheck/test/build/release-config/unpacked Linux build。
- `.github/workflows/release.yml`：`v*.*.*` tag + workflow_dispatch；stable/beta/alpha；mac arm64、mac x64、Windows x64、Linux x64 原生矩阵；签名、发布、上传、产物冒烟。
- `.github/workflows/nightly.yml`：每日 alpha macOS arm64 未签名归档，14 天保留。
- `scripts/check-version.mjs` 强制 package version 与 tag 一致。

### 5. 发布质量

- `scripts/ci-smoke.mjs`：启动下载的打包应用并依赖现有 smoke controller 退出码，180 秒超时保护。
- `docs/release/QA-CHECKLIST.md`：macOS / Windows / Linux 安装、签名、Git、更新、回滚、渠道人工检查清单。
- `scripts/verify-release-config.mjs`：9 项静态配置断言。

## 发布 gate（未经验证项，正式对外发布前必须闭环）

以下项目当前环境（macOS 无苹果/Windows/Linux 证书或私钥）**未能验证**，已在 `docs/release/QA-CHECKLIST.md` 中列为 🔒 发布 gate；任何渠道对外发布前必须完成并记录结果，且不得在 Release notes 中声称已验收。

- macOS Developer ID 签名、公证、staple/Gatekeeper：已交付 `scripts/notarize.cjs`、entitlements、`MACOS_CERTIFICATE`→`CSC_LINK/CSC_KEY_PASSWORD` 映射与 CI secret 流程；实际签名 + `spctl`/`codesign --verify` 验证未执行。
- Windows Authenticode / SmartScreen：`WIN_CSC_FILE`→`CSC_LINK/CSC_KEY_PASSWORD` 映射已接线并写入 README/workflow；实际签名与 `Get-AuthenticodeSignature` 验证未执行。
- Windows/Linux 安装包制作与实际安装：Release CI 原生矩阵与 electron-builder schema 已配置；本机未交叉构建，安装/签名须由对应原生 runner + 人工验收闭环。
