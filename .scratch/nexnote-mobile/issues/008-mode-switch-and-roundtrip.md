# MOB-008 编辑模式切换与零漂移验收

Ticket: MOB-008 · Milestone: M3 · Branch: dev/MOB-008 · Depends: MOB-007
Status: implemented —— 模式切换不写盘；14 项往返零漂移语料测试 + 6 项编辑流测试；截图 09/10/11

## 目标

把「两种编辑模式共享同一文档模型、切换无损」从设计规则变成可回归的验收证据，并锁定与桌面端的往返一致性。

## 行为

1. 源码模式 ↔ 块模式切换：切换不产生内容变化（切换本身不写盘、不产生提交）。
2. 编辑状态迁移：在任一模式下修改后切换到另一模式，内容一致且不丢失未保存修改。
3. 建立往返自动化用例：固定语料集（覆盖全部可编辑块类型 + 全部不支持结构）在「手机端编辑 → 写盘 → 桌面端解析 → 再写回」链路上对比字节与块结构。
4. 差异定位：用例失败时输出最小差异（哪一行、哪个块类型），用于定位是解析还是序列化问题。

## 边界

- 不追求与桌面块编辑器完全相同的块 ID 或内部表示，验收以文本字节与可解析结构为准。

## 验收

- 固定语料集全部往返一致（给出逐条用例结果）。
- 构造对抗场景：`[[双链]]` 出现在标题/表格/代码块内、连续空行、行尾空格、CRLF 文件、超大页面，均往返一致。
- 桌面端块编辑器打开手机端修改过的页面，无块结构漂移、无反链丢失（人工核对并记录）。

## 跨端往返证据（2026-09-30）

`.scratch/nexnote-mobile/verify/roundtrip-parity.test.ts` 用**桌面端真实块编辑器内核**（`packages/kernel` 的
`createEditor`）打开手机端导出的页面原文，验证两条不变式：

1. **未编辑文件逐字节未动**：4 个基线页面（index.md / notes/设备端同步.md / notes/基础编辑.md / refs/移动端计划.md）
   的设备端文本与远端初始提交逐字节一致 → 手机端没有改写无关内容。
2. **手机端写入的文件往返零漂移**：`Inbox/跨端核对笔记.md`（捕获产出）经桌面端内核 `getMarkdown()` 后
   与原文一致（忽略尾部换行），且 `[[设备端同步]]` 保留 → 桌面端打开无块结构漂移、双链不丢。

### 核对过程中确认的桌面端既有行为（非手机端缺陷）

`notes/基础编辑.md` 的表格经桌面端内核往返后单元格会被空格填充对齐
（`| 块类型 | 状态 | 说明 |` → `| 块类型 | 状态  | 说明    |`）。
该文件手机端只克隆读取、从未写过，且未编辑文件逐字节未动的核对已通过，
因此这是桌面端自身的 Markdown 序列化行为。已记入地图「范围外跟进」。
