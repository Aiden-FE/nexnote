# 07 · 产品架构对齐：模块边界与信息架构

Type: grilling
Status: resolved

## Question

全模块 MVP 的产品架构定稿（HITL，与用户对齐）：

1. 五大模块（块编辑文档、双链 & 元数据 & 知识关系、AI 融合、Git 底座、检索 Skill 系统）的边界与依赖关系图；插件系统横切各模块的方式。
2. 信息架构：库 → 页面 → 块的导航与组织模型（侧栏、面包屑、搜索入口、图谱入口）。
3. 产品行为：双链 / 别名 / 回链的交互、元数据编辑面、图谱视图的产品角色、置信度在 UI 的呈现位置。
4. AI 产品面：写作辅助的入口（块菜单 / 选区）、独立对话面板、会话保存为文档、上下文注入的选择器。
5. 插件与 Skill 的用户面：安装 / 启用 / 组合的最小产品闭环。

产出：产品架构定稿（后续整案原型的信息架构输入），新领域术语沉淀进 CONTEXT.md。研究票 01–06 的发现物（docs/research/）可作背景，但本票是产品层决策，不阻塞于研究。

## Answer

产品架构定稿（四轮 grilling 对齐，用户逐项确认；除置信度呈现采纳克制方案外均采纳推荐案）：

### 1. 模块边界与依赖

- **文档内核**（块编辑器 + 页面树）：消费存储层（MD + frontmatter 文件），被所有 UI 模块嵌入。
- **知识关系层**（双链/别名/标签/关系索引/图谱视图）：索引为可从 vault 全量重建的派生缓存（研究 04）。
- **Git 底座**：自动提交引擎 + 版本时间线 + 置信度计算；对外仅三个产品面：状态栏 / 时间线 / 设置。
- **AI 层**：Provider Adapter（OpenAI 协议）+ 写作辅助（三入口 + diff 回写）+ 对话 dock（上下文注入）+ 渐进召回管道（Skill 驱动；置信度作召回权重，后端行为）。
- **插件系统**：横切层，扩展块类型/命令/视图/菜单；检索 Skill 建模为一类受约束插件（详见 10 号票）。
- 依赖方向：UI（编辑器/图谱/对话）→ 内核服务（索引/Git/AI）→ 存储（vault 文件）；插件经 capability RPC 作用于 UI 与内核边界。

### 2. 信息架构

- vault = 根文件夹（git 仓库）；页面 = 单个 .md 文件；嵌套页面 = 子文件夹；文件名默认 = 页面标题（重命名联动文件与全库双链，高级设置可解耦）；链接按标题/别名解析。
- 主窗口：多 tab + 可分屏（左右≤2）+ 右侧可折叠 AI 对话 dock + 底部状态栏（分支/变更数/最后提交 + pull/push 快捷按钮带确认）。
- 侧栏：页面树（文件夹映射）+ 反向链接面板 + 标签面板；搜索双入口：⌘K 命令面板（页面跳转/命令/AI 动作）+ ⌘⇧F 全文搜索（含标题/别名/标签/块级命中）。
- 图谱：全局 + 局部（1–2 跳）都进 MVP，tab 内独立视图；过滤 = 标签/文件夹；高亮选中节点邻边；置信度不映射图谱颜色。

### 3. 行为细则

- **双链**：`[[` 补全（标题/别名/未建页面占位，点击创建）；回链呈现在侧栏面板。
- **元数据**：属性表格 UI ↔ YAML 源码双模式；frontmatter tags + 内联 #tag 双轨统一入关系索引。
- **置信度**：仅文档属性面板呈现（分数 + 构成因子）；参与 AI 召回排序（后端）。
- **AI 写作辅助**：三入口（选区浮动工具栏 / 斜杠命令 / 右键菜单），MVP 六动作：改写、扩写、缩写、润色、查漏补缺、补充论据；回写 = 替换类 diff 预览接受/拒绝，生成类追加新块可撤销，对话回答可插入为块；对话会话可保存为普通页面。
- **Git**：自动提交策略可配（方案见研究 03）；版本时间线（自动提交折叠分组、手动提交标注）；单篇回滚文件级 + hunk 级；高级用户可打开仓库目录。
- **Skill**：设置页「检索 Skill」分区管理（启用/禁用/排序/参数）+ 对话面板召回透明（参考来源 + 阶段标注，可展开）。
- **插件**：设置页本地安装（文件夹/zip）+ 安装时权限 diff 确认；贡献的块类型/命令/视图出现在对应菜单。
- **首启动**：向导三选一：新建空 vault（自动 git init）/ 打开本地文件夹（检测初始化 git，可识别 Obsidian vault）/ 克隆远程空仓库；导入入口后置设置页。
